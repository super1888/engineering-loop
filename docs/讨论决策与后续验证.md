# 讨论结论与后续验证

2026-09-21：保存已确认方向，便于恢复讨论；不保存完整聊天，也不要求使用 skill 的项目加载本文件。阶段执行规则仍以 SKILL.md 及其对应指南为准。

## 本轮已写入的决定

- **需求与变更**：持续澄清影响当前验收的问题；有现行需求时先说明新旧差异、已知影响和不确定项。复用已有授权，不机械增加审批；新决定明确替代哪些旧决定。
- **独立判断**：AI 给出有依据的建议与异议，接受新事实，也尊重有决定权的人知情后的选择。人的语气不证明技术正确，接受代价不等于代价消失。不猜测人际动机。
- **范围与自主程度**：区分已确认功能、必要工程保障和可选改进。根据影响范围、撤回成本与证据判断；范围内的局部选择自主推进，重要业务或架构变化交给开发者决定。
- **约束自身**：信息足够就行动，不反复规划、重问既定决定或重跑有效检查；完成当前目标与必要验证后结束，不自动启动优化循环。沟通与任务相称。
- **约束准入与退出**：从失败机制找合适防护，优先测试、工具和项目约定；通用规则必须同时检验收益与误伤，允许简化和删除。
- **团队能力可选**：公共协调服务只在存在协作需求时供开发者评估。本轮保留思路，不搭建、不安装，也不成为单人项目要求。
- **承诺边界**：skill 不能保证所有模型遵循，也不能直接限制内部推理。考察实际行动、产物、正确性及额外负担，不以自述合规为证据。

对应指南：[需求与取舍](../skills/engineering-loop/references/requirements.md)、[范围内实现](../skills/engineering-loop/references/implementation.md)、[项目与团队接入](../skills/engineering-loop/references/project.md)、[经验与规则评估](../skills/engineering-loop/references/learning.md)。

- 需求变化后正确替代旧规则；不会因为开发者坚持而虚构理由或抹去代价。

## 2026-09-22：参考项目继承与有效约定

本轮检查了两个既有项目的相关规范、代表性检查和变更记录；这里只保留脱敏后的方法，不复制项目代码、业务规则或私有路径。观察到的问题包括：目录相似但职责与调用方向偏离、项目入口指向失效版本、现行规则依赖多段历史覆盖，以及源码形式检查不足以证明实际交互。

已写入当前指导：

- 指定参考项目时，提取本次适用的职责、依赖和对象边界，记录合理差异；在复制同类实现前验证代表性功能。已有有效实现可复用，不增设固定审批阶段。
- 通用流程、可选择的技术栈或设计约定、项目业务规则分开沉淀；不把局部命名、注入方式或组件选择推广成全局要求。
- 维护可直接读取的有效约定和入口，保留替代关系；不让后续任务通过合并矛盾历史恢复当前规则，也不把最新提议或未提交实验当成已确认决定。
- 门禁对应明确的受保护规则和证据边界；验证违规与合法相邻案例。静态形式、依赖关系、实际交互和使用效果分别判断。
- 实现符合原约定但使用困难时，识别被事实挑战的假设，用范围受控的实验支持修正；保持已有授权和未受影响的验收条件。
- 用户纠正后明确适用范围，按已知原因检查相关遗漏；将需跨会话保留的约定落到共享实现、可信样例、门禁或可发现的现行指导。只有重要且反复出现的问题才考虑全新上下文验证，不要求每次小改都整理记忆或新增文档。

## 2026-09-22：多 agent 协作与规格纠错

已增加按需读取的[协作指南](../skills/engineering-loop/references/collaboration.md)，从项目接入、评审和验证引用；不要求每次任务启用多个 agent。

- 区分协调、实现、规格对齐审查（SDD）和测试验证（适用时使用 TDD）四种职责，可由较少 agent 承担，不规定固定人数或模型。
- 开发和审查都可以用事实挑战规格；协调者核对有效约定，在现有授权内处理工程选择。重要业务或架构取舍由有决定权的人确定，不能靠 agent 投票决定。
- 分歧说明当前规则、冲突场景、后果、建议和受影响工作；只暂停依赖未决事项的部分，独立工作继续。已确认决定不重复询问。
- 共享文件、契约、测试和集成责任明确归属；约定变化后发送差异并检查返回产物是否适配，收到通知不等于执行到位。
- 关键预期先于或并行于实现确定，依据已接受实例和独立证据；不照着实现补出必然通过的测试。
- 在代表性功能、重要契约变更、规格冲突和集成结果等有意义的边界检查，避免持续轮询半成品或重复有效验证。完成后停止，不因多 agent 自动增加审查轮次。

[四个新增协作场景](../evals/README.md#unreleased-collaboration-revision)尚未试跑。后续检验是否更早发现偏差，同时衡量重复检查和协调负担；不以角色数量或一致意见证明准确率提升。

## 2026-09-22：两条候选指导的首次对照

已执行[列表详情与文案 A/B 小型试验](../evals/results/2026-09-22-local-ui/report.md)。A 使用当前已提交 skill，B 仅叠加“分派前明确待解决的未知问题”和“围绕关键承诺寻找具体反例”；每种条件分别在全新上下文完成状态恢复修复和文案修改。

两组修复都通过独立浏览器验收 10/10，两组文案都通过文案及原行为保持检查 10/10；对应任务的最终源码字节一致。原有规则与公开测试均保留，文案任务没有扩展为导航修复。两组没有委派或向用户提问；代理自记证据不等于完整工具轨迹，耗时与 token 收益未测量。

本轮未观察到两条候选指导的额外正确性收益，因此暂不写入分发 skill。B 自行增加了部分浏览器组合，未改变独立验收结果；不能以测试数量推断收益。两组均遇到测试定位器问题，B 另有一次写入命令失败；这些执行成本保留在报告中，不据一次试跑归因于指导。

本轮验证的是两个新增可运行试验场景，不代表前述四个协作场景已通过，也未检验真实多 agent 契约协调。后续如继续评估，应选择新的契约分歧任务和合法对照，避免围绕已知解反复调规则。

## 2026-09-22：复杂异步导入与真实协作对照

已执行[异步导入 A/B 试验](../evals/results/2026-09-22-async-import/report.md)：每组使用全新协调者和两个实际前后端子代理，在相同初始文档冲突下开展独立工作，再于预定检查点接收逐行结果与失败行重试契约。两组都提出未决业务问题，没有重复询问已经确认的 100 行限制；最终有效文档、后端、HTTP 和 UI 一同采用修订后的契约。

两组均通过独立服务验收 8/8 和七个连续浏览器阶段，包括响应已丢失但后端已接受时的同标识恢复。原公开测试保留。两组产物不同，本次未观察到两个候选条款的额外正确性收益；总返工量、token 与协调负担没有完整测量，因此继续不改分发 skill。

本轮也发现验收器把“QUEUED：0 succeeded”误判为已完成。保留原误报和验收版本，使用合法计数与错误完成状态的正反对照修正规则，再用同一修订版检验两组；未修改候选来迎合错误检查。这是测试结论需要可挑战证据的实例，并不要求新增固定审查代理。

本次角色数和变更时机由统一提示指定，不能证明团队会自发正确分工，也没有比较独立 SDD/TDD 角色配置。已补可运行夹具、验收器、输入摘要、检查点与最终补丁及脱敏证据。更广的四个协作场景和跨真实项目迁移仍未完整验证；不能将这轮通过扩大为它们均已通过。
