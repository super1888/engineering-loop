## Post-run probe interpreter correction

The repeated setup failure also reproduced a narrower tool defect: `read_guard` invoked its own standard-library probe through `sys.executable` as supplied by the parent. If that spelling is a virtualenv symlink inside a denied checkout, the probe fails even when the caller’s target uses a permitted external interpreter. A real macOS regression first failed with the old helper, before any target dispatch. The helper now resolves only its probe interpreter to its actual file path; the caller’s target arguments and denied-directory policy are unchanged.

After the change, all seven read-guard controls passed, including the interpreter-alias regression and continued denial of the protected script. An independent reviewer reran those controls. This correction occurred after both model samples; their receipts describe the earlier helper and must not be treated as execution evidence for this later source change. It does not make a caller’s inaccessible target entrypoint usable or relax the read boundary.
