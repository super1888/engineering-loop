## Changes and outcome

- `inventory.py`: validate positive integer quantities (including order quantities); reject booleans and non-integers before any write.
- `receive` takes an SQLite immediate write transaction before reading request identity or remaining capacity. Existing receipt identity returns the stored original result; conflicting identity is rejected. Capacity and unknown-order failures leave the request ID unused.
- Order updates and receipt insertion commit atomically in the existing tables; exceptions roll back both. Existing schema, public method signatures and persisted rows are preserved.
- Added `tests/test_receipt_rules.py` with 10 focused tests. Existing `tests/test_inventory.py` is unchanged.

## Check status

- Baseline: FAIL, 1 of 3 tests failed, demonstrating duplicate stock increase (120 instead of 60).
- Final local suite: PASS, all 13 tests, exit code 0.
- Covered: original acceptance result after later receipts/reopen; globally immutable request identity; invalid quantity and unknown order rejection; exact capacity boundary; excessive receipt rejection and reuse of its ID; rollback after injected insert failure; competing connections for duplicate requests, excess aggregate quantity and cross-order ID reuse; existing stored rows.
- CI: UNRUN, fixture has no CI configuration.
- External evaluation: UNRUN and not inspected.
- No network, installation, external service, deployment or Git operation performed.

## Limitations

- Concurrency tests use two independent SQLite connections in separate threads and a synchronization barrier. They check representative competing operations, not exhaustive scheduler interleavings.
- SQLite keeps the existing five-second connection timeout. Prolonged external lock contention may surface an SQLite busy error; this exercise does not add a retry policy.
- Atomic rollback is verified with a failing SQLite trigger, not by power-loss or process-kill testing.
- No schema migration or inference of historical receipt identities was attempted; existing receipt records are used as stored.
