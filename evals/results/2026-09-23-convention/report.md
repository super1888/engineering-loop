# Project convention A/B trial, 2026-09-23

This local trial compared the committed skill before the convention guidance (`bdfaca1`) with its candidate revision (`4a255de`). Both received identical copies of the synthetic [order fixture](../../fixtures/convention-boundary/ORDER.md) and the same task prompt within each pair. Six fresh, sequential Codex CLI runs completed: amount change A/B, obsolete-comment correction A/B, and amount change with the installed Ponytail 4.10.0 skill explicitly loaded in full mode A/B. The Ponytail skill was read from the local installation and is not bundled here.

The CLI was version 0.146.1 on Windows. Runs used its account default model because an explicit `gpt-6-sol` selection was rejected as unsupported for this CLI account; the JSON events did not expose the default model identity. The valid runs used ephemeral sessions, ignored user config, did not delegate, and allowed edits in disposable synthetic workspaces. Tool permissions did not provide an external process sandbox; file access separation relied on the task instructions. The initially attempted amount-A run under a read-only profile changed no files and is excluded. Its subsequent write-enabled rerun used the same options as the other valid runs.

The independent evaluator was kept outside agent workspaces. Its unit tests had first demonstrated that the original amount fixture fails, a valid repair passes, and inlining the limit while deleting its reason fails. All six valid agent results passed their respective oracle modes; see [outcomes.json](outcomes.json), source patches, and final-agent messages in this directory. The evaluator's comment phrase is a tripwire, so the changed text and unrelated-file scope were also inspected manually. The alias produced by the Ponytail pair passed the accepted behavior; this fixture does not establish whether distinct function identities matter to callers in another project.

There is no observed correctness or scope advantage from the added implementation paragraph. One candidate run left weaker durable test coverage, but one run cannot establish that the guidance caused this difference. The candidate's project-skill routing and collaboration paragraphs were not loaded in these tasks, so this trial says nothing about automatic skill discovery or delegation. Explicitly loading Ponytail did not reproduce the reported HR project failures; this small fixture has unusually direct project rules. No human review-time or monetary-cost improvement was measured. CLI usage counts are recorded in `outcomes.json`, but cached and uncached token counts alone do not prove cost savings.

Each run tried `git status` in a workspace without a Git repository, yielding one failed command despite successful task checks. The first preparation helper also copied cached Python bytecode into each matched workspace; its hashes remain in `inputs.json`. The helper now initializes a synthetic Git baseline and excludes bytecode for future trials. Those corrections were made after these runs and do not retroactively change their evidence. Raw CLI JSONL remained in local disposable evidence directories; the committed artifacts retain path-neutral patches, final messages, usage and oracle results rather than a complete interaction transcript.

Decision: remove the unproven comment/constant paragraph from the distributed implementation reference. Keep the project-rule and specialist-routing candidates pending a separate routing test; rely on explicit project conventions for this demonstrated comment/constant case. A more representative held-out task is needed before claiming improved output quality in the HR project or under broad simplification skills.
