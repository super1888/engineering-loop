以下为个人记账第一版的最终验收说明。它覆盖收入、支出、完整增删改、历史记录、月份切换、本月汇总及本地持久保存，不缩减为单一示例。

# 个人记账 V1 验收说明

## 一、验收范围

第一版必须支持：

- 添加收入和支出
- 查看全部历史记录
- 修改任意记录
- 删除任意记录
- 切换月份查看对应记录和汇总
- 显示所选月份的总收入、总支出和结余
- 数据在同一台电脑、同一浏览器中持久保存

统一计算规则：

- 总收入 = 所选月份全部收入之和
- 总支出 = 所选月份全部支出之和
- 结余 = 总收入 − 总支出
- 月份按照电脑本地时区的自然月划分
- 金额单位为人民币元，界面统一保留两位小数

## 二、记录字段

每条记录必须包含：

| 字段 | 要求 |
|---|---|
| 类型 | 必填，只能是收入或支出 |
| 金额 | 必填，必须大于 0，最多两位小数 |
| 日期 | 必填，新增时默认今天 |
| 备注 | 选填，可以为空 |

第一版不要求分类、多币种、附件或账户字段。

# 三、逐项验收清单

## A. 首次打开与空状态

### A-01 首次使用

前置条件：浏览器中没有任何记账数据。

检查步骤：

1. 打开应用。
2. 查看默认月份。
3. 查看汇总和记录区域。

通过标准：

- [ ] 默认选中电脑本地日期所在月份。
- [ ] 总收入显示 `¥0.00`。
- [ ] 总支出显示 `¥0.00`。
- [ ] 结余显示 `¥0.00`。
- [ ] 页面明确显示“暂无记录”。
- [ ] 页面提供新增记录入口。
- [ ] 空状态下没有报错、空白数字或 `NaN`。

## B. 添加记录

### B-01 添加收入

输入：

- 类型：收入
- 金额：`5000`
- 日期：当前月份任意一天
- 备注：`工资`

通过标准：

- [ ] 保存成功后出现一条收入记录。
- [ ] 金额显示为 `¥5,000.00`。
- [ ] 日期和备注与输入一致。
- [ ] 总收入增加 `¥5,000.00`。
- [ ] 总支出不变。
- [ ] 结余增加 `¥5,000.00`。
- [ ] 不会重复创建两条相同记录。

### B-02 添加支出

继续添加：

- 类型：支出
- 金额：`35.50`
- 日期：当前月份任意一天
- 备注：`午餐`

通过标准：

- [ ] 保存成功后出现一条支出记录。
- [ ] 金额显示为 `¥35.50`。
- [ ] 总收入仍为 `¥5,000.00`。
- [ ] 总支出变为 `¥35.50`。
- [ ] 结余变为 `¥4,964.50`。

### B-03 添加无备注记录

输入合法的类型、金额和日期，不填写备注。

通过标准：

- [ ] 记录可以成功保存。
- [ ] 界面不会显示 `null`、`undefined` 等异常文字。
- [ ] 汇总正确更新。

### B-04 新增日期默认值

检查步骤：

1. 打开新增记录界面。
2. 不修改日期。

通过标准：

- [ ] 日期默认是电脑本地日期的今天。
- [ ] 用户仍可以修改为其他日期。

### B-05 添加其他月份记录

输入：

- 类型：收入
- 金额：`1000`
- 日期：上一个月
- 备注：`上月收入`

通过标准：

- [ ] 记录成功保存。
- [ ] 当前月份汇总不受影响。
- [ ] 切换到上一个月后能够看到该记录。
- [ ] 上一个月总收入增加 `¥1,000.00`。

## C. 输入校验

以下场景需要分别检查。

### C-01 类型为空

- [ ] 无法保存。
- [ ] 显示明确的类型必填提示。
- [ ] 不产生记录。
- [ ] 汇总不变化。

### C-02 金额为空

- [ ] 无法保存。
- [ ] 显示金额必填提示。
- [ ] 其他已填内容不丢失。

### C-03 金额为零

输入 `0` 或 `0.00`：

- [ ] 无法保存。
- [ ] 提示金额必须大于零。

### C-04 金额为负数

输入 `-10`：

- [ ] 无法保存。
- [ ] 提示金额必须大于零。

### C-05 金额不是有效数字

输入字母、符号组合或不完整数字：

- [ ] 无法保存。
- [ ] 显示明确的金额格式提示。
- [ ] 汇总中不出现 `NaN`。

### C-06 金额超过两位小数

输入 `12.345`：

- [ ] 无法保存。
- [ ] 提示金额最多保留两位小数。
- [ ] 系统不会静默改成另一个金额后保存。

### C-07 日期为空或无效

- [ ] 无法保存。
- [ ] 显示日期必填或格式错误提示。
- [ ] 不产生记录。

### C-08 校验失败后的表单状态

先填写多个字段，再制造一个校验错误并保存：

- [ ] 合法字段中的内容仍然保留。
- [ ] 用户修正错误后可以正常保存。
- [ ] 一次成功保存只创建一条记录。

## D. 记录列表

### D-01 显示所选月份记录

- [ ] 列表显示当前选中月份的全部记录。
- [ ] 不混入其他月份的记录。
- [ ] 每条记录显示类型、金额、日期和备注。
- [ ] 收入和支出在文字或视觉上可以明确区分。
- [ ] 每条记录都有编辑和删除入口。

### D-02 排序规则

准备多天、多笔记录：

- [ ] 不同日期按日期从新到旧排列。
- [ ] 同一天新增多笔时，后创建的记录排在前面。
- [ ] 刷新页面后顺序保持一致。

### D-03 查看全部历史记录

- [ ] 页面提供查看全部历史记录的入口。
- [ ] 全部历史记录包含所有月份的数据。
- [ ] 历史记录默认按日期从新到旧排列。
- [ ] 历史记录中的每一笔仍可编辑和删除。
- [ ] 从历史记录编辑或删除后，各月份汇总随之正确变化。

## E. 修改记录

### E-01 修改金额

将支出从 `¥35.50` 修改为 `¥30.00`。

通过标准：

- [ ] 原记录被更新。
- [ ] 不会新增第二条记录。
- [ ] 总支出减少 `¥5.50`。
- [ ] 结余增加 `¥5.50`。
- [ ] 修改后的备注、日期和类型保持不变。

### E-02 修改收入与支出类型

将一笔 `¥30.00` 支出修改为收入。

通过标准：

- [ ] 该金额从总支出中扣除。
- [ ] 该金额加入总收入。
- [ ] 结余按新类型正确重新计算。
- [ ] 列表中的类型标识同步更新。

### E-03 修改日期但不跨月

将记录修改到同一个月的另一日。

通过标准：

- [ ] 月度汇总不变化。
- [ ] 日期正确更新。
- [ ] 记录按照新日期重新排序。

### E-04 修改日期并跨月

将一笔记录从当前月改到上一个月。

通过标准：

- [ ] 记录从当前月列表消失。
- [ ] 当前月汇总移除该笔金额。
- [ ] 切换到上一个月后可以看到该记录。
- [ ] 上一个月汇总加入该笔金额。
- [ ] 全部历史记录中只有一条该记录。

### E-05 修改备注

- [ ] 备注可以从有内容改为空。
- [ ] 备注可以从空改为有内容。
- [ ] 修改备注不会改变汇总金额。

### E-06 取消修改

进入编辑状态并改变内容，然后取消：

- [ ] 原记录没有变化。
- [ ] 汇总没有变化。
- [ ] 刷新后仍为修改前的数据。

### E-07 编辑时输入无效内容

- [ ] 使用与新增记录相同的校验规则。
- [ ] 校验失败时原记录不被破坏。
- [ ] 修正错误后可以保存。

## F. 删除记录

### F-01 取消删除

点击某条记录的删除按钮：

- [ ] 显示确认提示。
- [ ] 提示中包含足以识别记录的信息，如类型、金额、日期或备注。
- [ ] 选择取消后，记录仍然存在。
- [ ] 汇总不发生变化。

### F-02 确认删除收入

- [ ] 记录从列表消失。
- [ ] 总收入扣除该笔金额。
- [ ] 总支出不受影响。
- [ ] 结余同步减少。
- [ ] 刷新后被删除记录不会恢复。

### F-03 确认删除支出

- [ ] 记录从列表消失。
- [ ] 总支出扣除该笔金额。
- [ ] 总收入不受影响。
- [ ] 结余同步增加。
- [ ] 全部历史记录中也不再出现该记录。

### F-04 删除其他月份记录

- [ ] 可以从历史记录中删除其他月份的记录。
- [ ] 删除只影响该记录所属月份的汇总。
- [ ] 当前查看月份不相关时，其汇总保持不变。

## G. 月份切换与月度汇总

### G-01 切换上一个月

- [ ] 可以从当前月切换到上一个月。
- [ ] 月份标题正确变化。
- [ ] 列表只显示上一个月的记录。
- [ ] 总收入、总支出和结余均按上一个月重新计算。

### G-02 切换下一个月

- [ ] 可以切换到下一个月。
- [ ] 没有记录时显示三个 `¥0.00` 和空状态。
- [ ] 不会继续显示上一个月份的汇总或记录。

### G-03 返回当前月

- [ ] 页面提供返回当前月的清晰方式。
- [ ] 返回后重新显示当前月记录和汇总。

### G-04 月份边界

分别创建：

- 某月最后一天的记录
- 次月第一天的记录

通过标准：

- [ ] 两笔记录分别归入正确月份。
- [ ] 切换月份时不会重复出现或遗漏。
- [ ] 两个月的汇总分别只包含自己的记录。

### G-05 负结余

某月支出大于收入，例如：

- 收入 `¥100.00`
- 支出 `¥150.00`

通过标准：

- [ ] 总收入显示 `¥100.00`。
- [ ] 总支出显示 `¥150.00`。
- [ ] 结余明确显示 `-¥50.00` 或等价的负数格式。
- [ ] 不会把负结余显示为零。

### G-06 小数金额计算

创建：

- 收入 `0.10`
- 收入 `0.20`
- 支出 `0.15`

通过标准：

- [ ] 总收入显示 `¥0.30`。
- [ ] 总支出显示 `¥0.15`。
- [ ] 结余显示 `¥0.15`。
- [ ] 不出现 `0.30000000000000004` 等精度错误。

## H. 本地保存与恢复

### H-01 刷新恢复

新增、修改和删除若干记录后刷新页面：

- [ ] 新增记录仍然存在。
- [ ] 修改结果仍然存在。
- [ ] 已删除记录不会恢复。
- [ ] 月度汇总与保存的数据一致。

### H-02 关闭浏览器后恢复

关闭浏览器，再使用同一浏览器打开应用：

- [ ] 历史记录仍然存在。
- [ ] 所有月份的汇总仍然正确。
- [ ] 不需要登录。

### H-03 重启电脑后恢复

重启电脑，再使用同一浏览器打开应用：

- [ ] 记录仍然存在。
- [ ] 可以继续添加、修改和删除记录。

### H-04 数据使用边界

- [ ] 应用不要求注册账号。
- [ ] 应用不依赖云端同步。
- [ ] 不承诺在其他浏览器或其他电脑中看到数据。
- [ ] 清除该网站的浏览器数据后，允许数据丢失。
- [ ] 页面应以合适方式说明数据仅保存在当前浏览器。

## I. 完整业务场景

依次执行：

1. 在本月添加收入 `¥5,000.00`，备注“工资”。
2. 在本月添加支出 `¥35.50`，备注“午餐”。
3. 在本月添加支出 `¥1,200.00`，备注“房租”。
4. 在上个月添加收入 `¥1,000.00`。
5. 将午餐支出修改为 `¥30.00`。
6. 删除本月房租支出。
7. 切换到上个月，再返回本月。
8. 刷新页面。

本月最终结果必须为：

- [ ] 总收入 `¥5,000.00`
- [ ] 总支出 `¥30.00`
- [ ] 结余 `¥4,970.00`
- [ ] 本月列表只有工资收入和午餐支出
- [ ] 午餐金额为修改后的 `¥30.00`
- [ ] 已删除的房租记录不存在

上个月最终结果必须为：

- [ ] 总收入 `¥1,000.00`
- [ ] 总支出 `¥0.00`
- [ ] 结余 `¥1,000.00`
- [ ] 能看到上月收入记录

刷新后：

- [ ] 上述记录和汇总全部保持一致。
