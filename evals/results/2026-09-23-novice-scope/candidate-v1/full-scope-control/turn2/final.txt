# 个人记账第一版验收说明

以下内容为完整第一版的行为验收标准。验收时应逐项检查；收入、支出、新增、修改、删除、本月汇总和本地持久保存缺一不可。

## 一、验收范围

每条记账记录包含：

- 类型：收入或支出，必填
- 日期：必填，允许任意有效日期
- 金额：必填，必须大于 0，最多两位小数
- 备注：选填

本月汇总包含：

- 本月总收入
- 本月总支出
- 本月结余

其中：

`本月结余 = 本月总收入 − 本月总支出`

“本月”以用户电脑的本地日期和自然月为准。

## 二、逐项验收清单

### A. 初始状态

- [ ] A01：首次打开且没有任何记录时，页面可以正常使用。
- [ ] A02：本月总收入显示 `0.00`。
- [ ] A03：本月总支出显示 `0.00`。
- [ ] A04：本月结余显示 `0.00`。
- [ ] A05：记录列表清楚表达当前没有记录，而不是显示错误或空白故障页面。

### B. 添加收入

操作：新增一条本月收入，日期选今天，金额填写 `5000`，备注填写“工资”。

- [ ] B01：可以明确选择“收入”类型。
- [ ] B02：记录保存成功。
- [ ] B03：列表中出现且只出现一条对应记录。
- [ ] B04：记录显示为收入、日期正确、金额显示 `5000.00`、备注显示“工资”。
- [ ] B05：本月总收入变为 `5000.00`。
- [ ] B06：本月总支出仍为 `0.00`。
- [ ] B07：本月结余变为 `5000.00`。

### C. 添加支出

操作：新增一条本月支出，金额填写 `1200.50`，备注填写“房租”。

- [ ] C01：可以明确选择“支出”类型。
- [ ] C02：记录保存成功。
- [ ] C03：列表中同时保留工资收入和房租支出，共两条记录。
- [ ] C04：房租记录的类型、日期、金额和备注正确。
- [ ] C05：本月总收入仍为 `5000.00`。
- [ ] C06：本月总支出变为 `1200.50`。
- [ ] C07：本月结余变为 `3799.50`。

### D. 添加其他月份记录

操作：新增一条上个月的支出，金额填写 `300`。

- [ ] D01：系统允许选择上个月的有效日期。
- [ ] D02：记录可以成功保存并出现在列表中。
- [ ] D03：本月总收入仍为 `5000.00`。
- [ ] D04：本月总支出仍为 `1200.50`。
- [ ] D05：本月结余仍为 `3799.50`。
- [ ] D06：上月记录未被错误计入本月汇总。

再新增一条未来日期记录：

- [ ] D07：系统允许保存未来有效日期。
- [ ] D08：若未来日期不属于本月，该记录不影响本月汇总。

### E. 修改金额与备注

操作：将“房租”支出的金额从 `1200.50` 修改为 `1000`，备注改为“房租调整”。

- [ ] E01：可以从已有记录进入编辑状态。
- [ ] E02：编辑时能够看到原有数据。
- [ ] E03：保存后仍是原来那一条记录，没有产生重复记录。
- [ ] E04：金额显示为 `1000.00`。
- [ ] E05：备注显示为“房租调整”。
- [ ] E06：本月总收入仍为 `5000.00`。
- [ ] E07：本月总支出变为 `1000.00`。
- [ ] E08：本月结余变为 `4000.00`。

### F. 修改记录类型

操作：把上述 `1000.00` 的本月支出改为收入。

- [ ] F01：类型可以从支出修改为收入。
- [ ] F02：保存后记录显示为收入。
- [ ] F03：本月总收入变为 `6000.00`。
- [ ] F04：本月总支出变为 `0.00`。
- [ ] F05：本月结余变为 `6000.00`。
- [ ] F06：同一金额没有同时计入收入与支出。

随后将该记录改回支出，以便继续验收。

### G. 修改记录日期

操作：把本月的 `1000.00` 支出日期改为上个月。

- [ ] G01：修改可以成功保存。
- [ ] G02：记录的新日期显示正确。
- [ ] G03：该记录不再计入本月总支出。
- [ ] G04：本月总收入为 `5000.00`。
- [ ] G05：本月总支出为 `0.00`。
- [ ] G06：本月结余为 `5000.00`。

随后把日期改回本月：

- [ ] G07：本月总支出恢复为 `1000.00`。
- [ ] G08：本月结余恢复为 `4000.00`。

### H. 取消修改

操作：再次编辑工资收入，将金额改成 `9999`，但选择取消。

- [ ] H01：取消后仍显示原金额 `5000.00`。
- [ ] H02：原类型、日期和备注均未改变。
- [ ] H03：本月汇总没有改变。
- [ ] H04：刷新页面后也没有出现被取消的修改。

### I. 删除及删除确认

操作：对工资收入执行删除。

- [ ] I01：删除前出现明确的确认提示。
- [ ] I02：第一次选择取消删除后，记录仍然存在。
- [ ] I03：取消删除不会改变汇总。
- [ ] I04：再次删除并确认后，工资记录从列表中消失。
- [ ] I05：其他记录不受影响。
- [ ] I06：本月总收入变为 `0.00`。
- [ ] I07：本月总支出为 `1000.00`。
- [ ] I08：本月结余显示 `-1000.00`，负结余能够正确呈现。
- [ ] I09：刷新页面后，被删除的记录不会重新出现。

### J. 必填项校验

分别尝试提交以下记录：

- 未选择类型
- 未填写日期
- 未填写金额

每种情况均应满足：

- [ ] J01：记录未被创建。
- [ ] J02：页面明确指出具体缺失的字段。
- [ ] J03：用户已经填写的其他内容不会无故丢失。
- [ ] J04：记录列表和本月汇总没有改变。

### K. 金额校验

分别输入：`0`、`-10`、非数字文本、超过两位小数的金额。

- [ ] K01：金额为 `0` 时不能保存。
- [ ] K02：金额为负数时不能保存。
- [ ] K03：金额不是有效数字时不能保存。
- [ ] K04：超过两位小数时不能保存，并给出明确提示。
- [ ] K05：每次校验失败都不会创建或修改记录。
- [ ] K06：校验失败不会改变汇总。
- [ ] K07：整数金额保存后以两位小数显示。
- [ ] K08：一位小数金额保存后以两位小数显示。

### L. 日期校验

- [ ] L01：无效日期不能保存。
- [ ] L02：日期缺失时能明确提示。
- [ ] L03：合法的过去日期可以保存。
- [ ] L04：合法的未来日期可以保存。
- [ ] L05：只有日期处于用户电脑当前自然月的记录才计入本月汇总。

### M. 备注行为

- [ ] M01：备注为空时可以保存记录。
- [ ] M02：空备注不会被误报为必填项缺失。
- [ ] M03：填写备注后，列表能正确显示。
- [ ] M04：备注可以被修改。
- [ ] M05：取消修改时保留原备注。

### N. 防止重复提交

操作：添加记录时快速连续触发两次保存。

- [ ] N01：一次保存操作只产生一条记录。
- [ ] N02：汇总金额只计算一次。
- [ ] N03：用户能够明确知道保存是否成功。

### O. 汇总计算与显示

准备以下本月记录：

- 收入 `5000.00`
- 收入 `200.25`
- 支出 `1200.50`
- 支出 `99.75`

预期结果：

- [ ] O01：本月总收入为 `5200.25`。
- [ ] O02：本月总支出为 `1300.25`。
- [ ] O03：本月结余为 `3900.00`。
- [ ] O04：修改任意一条记录后，三个汇总值立即按最新记录重新计算。
- [ ] O05：删除任意一条记录后，三个汇总值立即重新计算。
- [ ] O06：汇总金额统一显示两位小数。
- [ ] O07：结余允许为正数、零或负数。
- [ ] O08：计算过程中没有明显的浮点误差，例如不显示 `0.30000000000000004`。

### P. 本地持久保存

- [ ] P01：刷新页面后，已保存的记录仍然存在。
- [ ] P02：刷新后汇总结果与刷新前一致。
- [ ] P03：关闭浏览器后重新打开页面，记录仍然存在。
- [ ] P04：关闭后重开，修改过的内容保持最新状态。
- [ ] P05：关闭后重开，已删除的记录不会恢复。
- [ ] P06：整个使用过程不要求注册或登录。
- [ ] P07：断开网络后，核心记账、修改、删除和汇总功能仍可使用。

## 三、已确认的使用边界

第一版只供当前用户在自己的电脑浏览器中使用：

- 数据保存在当前浏览器本地。
- 不要求服务器或云端账户。
- 不要求跨电脑、跨浏览器同步。
- 换浏览器、清理浏览器数据或电脑损坏后，数据可能丢失。
- 第一版不提供云备份、账单导入、多币种、预算、图表、多人账本或历史月报表。

## 四、整体验收通过条件

只有同时满足以下条件，第一版才算通过：

- 所有必需功能均实际可操作，不是静态展示。
- 收入和支出都能新增、修改及删除。
- 所有汇总结果与记录数据一致。
- 本月与非本月记录的统计边界正确。
- 输入错误不会产生脏记录或错误汇总。
- 刷新和重开浏览器后数据仍然存在。
- 上述检查项全部通过，没有阻断日常记账的已知问题。

这份说明即为第一版的行为合同；后续实现和测试应以此为准，不再把范围缩减为单一支出场景。
