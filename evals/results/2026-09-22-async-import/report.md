## 条件与控制

- 起点：`8962b78` 的 skill，新增独立合成导入夹具；准确输入、提示和变更消息见 [inputs.json](inputs.json)。前一轮实现和独立验收内容不提供给候选。
- Codex desktop，本机 Windows；每组全新协调者上下文，继承可用模型配置，无覆盖。完整解析模型标识、采样参数、token、总工作量及开发耗时未取得。
- Python 3.12.3、Node 24.14.1、Playwright 1.62.1、Edge 153.0.4234.48。没有安装依赖、访问业务服务或发布。
- 按 A、B 顺序运行；每组协调者与两个前后端子代理实际协作，根评估者占用剩余并发位置。角色数、文件所有权约束和变更检查点由统一提示规定。
- 两个开发者检查各自输入并开始独立工作后，协调者发送 CHECKPOINT_READY；评估者记录当时的代理状态和源码，放入同一份 OWNER_CHANGE.md，再发送冻结的 owner 回复。其余实现与自测由候选自行完成。
- 初始需求与接口文档在失败后保留成功结果还是原子回滚上冲突；100 行上限已有决议。owner 变更确认部分成功，新增逐行结果、仅失败行重试、持久请求标识与响应丢失恢复。

这是程序约定的目录隔离，不是安全沙箱。协调记录和命令证据主要由代理自行维护，根评估者可观察检查点消息、代理状态和最终产物；没有完整宿主调用轨迹。证据中的本机目录和用户标识已脱敏。

## 重放方式

复制仓库的 `evals/fixtures/async-import` 到全新临时目录，在其中执行 `git init`，再以该目录为工作目录执行 `git -c core.autocrlf=false apply --whitespace=nowarn <补丁绝对路径>`。这里不自动修复候选的换行或空白，以保留原始证据。最终候选补丁包含评估者下发的 OWNER_CHANGE.md；无需另行注入。按[运行协议](../../README.md#asynchronous-import-and-live-owner-change-ab-trial)执行原公开测试及两个独立验收器。

补丁保留源码的实际换行字节，仓库属性禁止对这些补丁自动转换换行。源码摘要不含 Python 缓存和临时数据库；命令日志是脱敏后的文本，不能将其直接当成完整可执行录制。代理生成的截图没有作为本轮视觉设计结论，未随文本证据留存的二进制文件仅记录摘要。

准备阶段发现生成的 Python 缓存被同时复制给两组。保留原始清单及其摘要，没有重建任何一组；后续准备脚本已排除缓存。源码与验收未改，说明见 [setup-notes.json](setup-notes.json)。缓存不作为发布产物或重放目标。

## 验收器校验

后端验收先由独立代理依据公开契约编写，浏览器验收启动真实 HTTP 服务，通过手动释放 worker 确定运行阶段。评估者另写临时正向参考实现，未提供给候选。

| 控制 | 结果 |
|---|---|
| 未实现基线 | 公开验证测试 2/2；服务验收 8 项报错；浏览器在提交收到 501 时失败 |
| 独立正向参考 | 公开测试 2/2；服务验收 8/8；浏览器七个连续检查阶段通过 |
| 删除持久重试去重的变体 | 服务验收检出“再次失败后重复旧请求又排队”的错误 |
| 响应丢失后生成新标识的变体 | 浏览器验收在同标识恢复阶段失败 |

原始结果与可重放参考补丁见 [controls.json](controls.json)、[positive-reference.patch](positive-reference.patch)、[mutant-forgotten-retry.patch](mutant-forgotten-retry.patch)、[mutant-new-retry-key.patch](mutant-new-retry-key.patch)。两个负向控制检出特定缺陷，不等于验收器覆盖所有缺陷。

初次检查 A 时，浏览器验收把合法的 `QUEUED: 0 succeeded, 0 failed, 2 total` 误报为接收即完成。保留[原始误报](A-browser-v1-false-positive.txt)和[初版验收器](browser-oracle-v1.cjs.txt)，仅删除会误判汇总计数的负向关键词检查；原有排队状态与逐行结果断言保留。独立作者复核了修复范围。新增[合法计数正向控制](positive-queued-counts.txt)通过，[确实显示 Completed 的负向控制](mutant-acceptance-completed.txt)仍失败。A 的源码未动，A/B 均用相同修订版评估；不能把这次误报算成候选缺陷。

## 证据边界

这轮的复杂度来自跨层状态、持久化、并发调用和运行中的约定改变。它覆盖一个新增的可运行协作场景；并未完整执行此前四个协作场景及各自的合法对照。

固定分工与预定检查点不能证明代理能自发选择恰当团队或时机；本轮也没有独立比较 SDD、TDD 职责配置。一次匹配试跑不能证明减少返工或提高总体准确率。浏览器采用确定性的 worker 调度，服务并发检验为有限样本；进程崩溃恢复、生产负载、跨设备同步、视觉审美和跨真实项目迁移均未验证。

候选收到独立验收反馈前的结果才算本次观测，不以按隐藏失败修好后的版本替换初始结果。重放只用于核对留存产物，不算新增模型样本。

本轮保留现有 skill，不把两个候选条款升级为强制门禁。可支持的经验是：协作产物需要跨层验收，验收规则本身也允许被合法案例纠正；本轮测试误报是具体实例。不能据此推出必须增加专职代理、固定检查次数或更多日常文档。

仓库验证：分发/链接/元数据检查通过，单元测试 5 项通过、1 项因 Windows 主机不允许建立测试符号链接而跳过；Python 与 Node 语法检查通过。准备脚本排除缓存的修正已用独立临时目录验证。见 [repository-checks.txt](repository-checks.txt)。这些包装检查与模型试跑结果分开计数，未声明新的远端 CI 结果。
