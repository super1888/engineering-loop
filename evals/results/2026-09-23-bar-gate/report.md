# Golden-set, blind-review and quality-gate pilot, 2026-09-23

This pilot tested the current requirements guidance against an earlier version on two matched bar-ordering tasks. The [golden suite](../../goldens/bar-boundaries-v1.json) freezes the task, business facts and rubric before execution. One case leaves online off-menu requests undecided while allowing manager-approved staff handling; the control explicitly prohibits all off-menu orders. Both include an unclear item, a listed but sold-out drink, a normal stocked drink and an unresolved shortage after acceptance. The criteria are kept outside implementing workspaces.

`prepare_bar_trial.py --baseline-ref c58b802` created four disposable Git workspaces from the same fixture within each case. Each received the current skill snapshot; the baseline arm replaced only `references/requirements.md` with revision `c58b802`. The candidate arm used the skill at source revision `54bf4dc`. Prompts differed only in workspace path. The [input manifest](input-manifest.json) records hashes. Four fresh, sequential Codex CLI 0.146.1 runs on Windows used the account-default model, whose identity was not exposed by JSON events. Runs were ephemeral, ignored user configuration, disallowed delegation and publication, and allowed writes only by instruction rather than an external process sandbox. All four completed, read the requirements reference and changed only `REQUIREMENTS.md`; [outcomes.json](outcomes.json) records usage and command counts.

`blind_gate.py prepare` randomized left/right placement per case and wrote the [review packet](blind-packet.json) separately from the private [mapping](unblinded-key.json). The packet exposed task facts, rubric and the four resulting documents but no arm names or workspace paths. A fresh Codex CLI instance read only that packet and its own review file; the [blinded review](blind-review.json) rated both arms passing on every rubric item and tied them on both cases. The mapping was revealed only after the review was written: candidate was left in the undecided case and right in the prohibition control. An initial reviewer launch failed before reading the packet because its directory was not a Git repository; the valid run used `--skip-git-repo-check`. This is a model review, not a human domain judgment.

After the review was frozen, the gate implementation was hardened to bind the golden-suite hash as well as artifact and packet hashes, and to normalize CRLF/LF before hashing so Git checkout does not invalidate unchanged text. The recorded private key gained the normalized hashes without changing its arm mapping or the review packet content; both decisions were replayed against the stored artifacts. Future packets include these hashes at preparation time.

The [pilot gate](pilot-decision.json) passed: no observed regression under the model review. The same evidence [failed the release gate](release-decision.json) because a human blinded review has not occurred. Unit tests also show that a critical failure or baseline preference blocks, and changes to either an artifact or the frozen rubric invalidate a review. The release command returns nonzero on failure. It checks the review's declared `reviewer_kind`; reviewer identity is a process responsibility, not authenticated by this local script. The test does **not** establish quality improvement, lower cost, a production pass rate, or readiness to publish. Both arms produced accepted-looking requirements in this small synthetic pair; only one trial per arm and case was run. The visible golden suite is a development set, not a secret holdout. A human reviewer and repeated, varied tasks are needed before using this as a release decision.

To repeat from a new disposable root, run `python evals/prepare_bar_trial.py --baseline-ref c58b802`, execute each generated prompt with the same CLI options, and create a runs manifest pointing at the four `REQUIREMENTS.md` files. `python evals/blind_gate.py prepare --suite evals/goldens/bar-boundaries-v1.json --runs <runs.json> --packet <reviewer/packet.json> --key <private/key.json>` creates the blinded packet and mapping. After an independent reviewer fills the rubric, `python evals/blind_gate.py gate` with those four paths plus `--review` and `--output` enforces the release profile; `--pilot` explicitly allows a model-only exploratory review. Keep the key inaccessible to reviewers until their review is frozen.
