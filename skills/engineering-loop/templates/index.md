# 六阶段交付模板

先从 [当前阶段](../SKILL.md) 的交付物要求确定要记录的内容。已有文档、任务卡或证据记录时沿用原样式和位置，保留可回查的版本。需要新建记录时，优先用项目现有格式。项目没有适用格式时，按本次范围选用对应模板和章节。

| 阶段 | 模板 | 可沿用的产物 |
|---|---|---|
| 01 需求分析与确认 | [0→1 首期需求分析与确认](requirements.md) · [1→10 需求与修改情况说明](requirements-change.md) | 首期调研、痛点、访谈和确认记录，或现有系统的新增与修改记录、已有需求文档或 PMS 卡 |
| 02 方案设计与规划 | [启动计划](kickoff-plan.md) | 产品设计方案、技术设计方案、开发任务与排期表、模块分工与开工检查 |
| 03 开发与联调 | [模块开发与自测记录](development-record.md) | 实现和自测证据、适用的评审与交接记录 |
| 04 测试与验收 | [测试与验收记录](acceptance-record.md) | 测试方案与用例记录、发布前的缺陷跟踪与测试验收记录 |
| 05 发布与验证 | [发布与验证记录](release-record.md) | 发布计划与部署记录、发布及上线验证记录 |
| 06 持续运维 | [持续运维记录](operations-record.md) | 运行观察与处置、线上缺陷及引用的 04 验收记录 |

与行为、验收、权限或实际依赖有关的关键缺口，先核对已有事实，再按[公共拷问](../references/grill.md)及时向能确认的人提问。样式、字段和项目细则尚未定下时可先留待定；影响交付时注明影响范围和确认人。

交接引用上游已确认的版本、任务及证据。根据本次实际工作选择阶段和记录。涉及 PMS 写入时使用[连接与任务规则](../references/pms.md)。
